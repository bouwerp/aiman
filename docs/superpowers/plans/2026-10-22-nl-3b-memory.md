# NL-3b Memory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shared context gets typed notes with supersede and expiry, a measured FTS5 index in serve's DB, ranked compact `context.find`, ranked packs, and a memory-candidate loop (serve queues, laptop proposes, user accepts).

**Architecture:** `domain.ContextEntry` gains `Type`, `Supersedes`, `ValidUntil` in frontmatter. Ranking and expiry are one pure function shared by the scan path and the index path. `contextstore.Index` wraps an FTS5 table plus a metadata table in serve's SQLite file; `Files` uses it only when serve attaches it, and falls back to today's walk when it is missing or broken. Serve reindexes files newer than a stored mtime high-water mark on start. Serve's handover writer (plan 3a) enqueues a memory job; the TUI fetches jobs when its event stream connects, runs the local summariser, and shows proposals under the Admin menu.

**Tech Stack:** Go 1.26, `modernc.org/sqlite` v1.46.1 (FTS5 confirmed working while planning: prefix query `"sess"* "cook"*` matched), `gopkg.in/yaml.v3`, Ollama via `internal/infra/ai`, Bubble Tea v2.

**Spec:** `docs/superpowers/specs/2026-10-22-aiman-next-level-design.md` (Constraints, Shared interfaces, W6b). **Depends on:** `docs/superpowers/plans/2026-10-22-nl-3a-handover.md` (Tasks 3–4: `Server.writeHandover`, `handoverNoteID`) and nl-1 Task 3a (`aiman rpc` allowlist, `usecase.ServeRPC`). **Must land before nl-7**, which stores reviews as `Type: review` notes.

## Global Constraints

- Go 1.26; Bubble Tea v2, Bubbles v2, Lip Gloss v2 only. Tests use `pressKey`/`pressRune`.
- `make ci` green before every commit. `TestOllamaIntelligenceSummariseSession` is a known failure.
- No socket method blocks longer than 30 s. `memory.jobs` and `memory.done` are single queries.
- SQLite is `modernc.org/sqlite`. Serve is the only writer of the context index and the memory-job queue; other processes go through the socket.
- Note types are exactly `decision|pitfall|convention|fact|handover|review|summary`. Notes without a type read as `fact`.
- Packs and search skip superseded and expired notes, and rank `decision`, `pitfall`, `convention` before others, then recency (newest first).
- The summariser stays on the laptop; candidates are saved only after the user accepts; at most 5 per job.
- Noise budget: no toast, header or row change for memory candidates.
- Import graph: `gateway` → `server` → `usecase`; `contextstore` must not import `infra/sqlite` (it takes a `*sql.DB`).

## Review Focus

- `context find` text containing FTS syntax (`"`, `-`, `:`, `*`, `(`, `NEAR`, `OR`): no SQL error, results equal to a plain-word search of the same tokens. Test in Task 4.
- A note edited or deleted on disk while serve was down: reflected after serve restarts (edit reindexed, deleted file gone from results). Test in Task 5.
- `valid_until` that does not parse, or `type: Banana`, in a hand-edited note: the note still loads (unknown type → `fact`, bad date → no expiry), never silently disappears. Test in Task 2.
- Index cannot open (read-only or locked DB): serve starts, find/pack fall back to the scan and still return the right notes. Test in Task 5.
- Summariser returns 8 candidates, an empty title, or type `handover`: capped to 5, invalid ones dropped, job stays queued when the summariser is unavailable. Test in Task 8.

# nl-13: Drop tmux (spec + plan)

User decisions (2026-10-28): tmux support is removed completely. The built-in PTY runtime in `aiman serve` is the only terminal. **Zero tmux code remains** (no legacy shim). `TmuxSession` is renamed to `TerminalName`. mosh is removed (only tmux attach used it). Lands after nl-12 (handover child).

## 1. Spec

### TmuxSession is the generic terminal name
It is the PTY display name (`flow_manager.go:1012,1022`; `ptyruntime.Spec.Name`), the discovery/merge dedupe key (`session_discoverer.go`, `internal/ui/session_merge.go`), the UI preview key, the `resolveSession` address and the row label. Rename the Go field to `TerminalName` and `SanitizeTmuxSessionName` to `TerminalNameFromBranch` (behaviour unchanged). Keep: the sqlite column `tmux_session` and its COALESCE rule, the wire key `tmux_session` on `SessionInfo`/`session_create_remote.go`/`api/openapi.yaml`, and the `session.register` key via `json:"TmuxSession"` on the renamed field.

### Backend
| Stored | Meaning | Written by |
|---|---|---|
| `pty` | normal session | every create, restart, live PTY discovery |
| `tmux` | legacy row, never revived automatically | old binaries, and the one-time NULL migration |
| `""` | no terminal recorded | discovery; never treated as legacy |

All routing goes to pty without a backend branch. The only remaining check is `Session.IsLegacyTmux()`. Delete `IsPTY`, `BackendTmux`, `DefaultSessionBackend`, `ResolveSessionBackend`, `SessionConfig.SessionBackend`.

**Bug fix.** `sessionBackend()` (`internal/infra/sqlite/repository.go:668-674`) turns `""` into `"tmux"`, which passes `COALESCE(NULLIF(excluded.backend,''), ...)`, so discovery saves relabel live pty rows as tmux. Save writes `s.Backend` as given; a one-time `UPDATE sessions SET backend='tmux' WHERE backend IS NULL` keeps what the old normaliser implied.

### Legacy tmux sessions (zero tmux code)
- Nothing runs on remotes at upgrade; tmux processes keep running and their hooks still report.
- TUI shows a legacy row on a scanned host as INACTIVE with `tmux (legacy) · stop it on the host, then s` (memory only, never saved). Today the merge drops undiscovered rows on scanned hosts (`dashboard.go:7127-7130`); legacy rows are the exception. One startup toast: `N sessions still use tmux. aiman no longer runs tmux. Run "tmux kill-session -t <name>" on the host, then press s to move it to pty.`
- Attach and revive refuse legacy rows (`ErrLegacyTmuxSession`, carrying the hint and the exact `tmux kill-session -t '=<name>'` command to run on `<host>`). Auto-revive would put two agents on one conversation.
- `s` restart on a legacy row: show a confirm screen with the host and the exact command to stop the tmux session; on confirm (user says it is stopped) write the handover, `RecreatePTYSession` with native resume, set `Backend="pty"`, save. aiman never runs tmux itself.
- Terminate on a legacy row: same confirm screen before the worktree is removed, so the worktree is not deleted under a live agent.
- Serve `session.list` reports legacy rows `inactive`; `session.prompt` to one returns `legacy_terminal`; steer holds with `legacy_terminal`.

### Discovery without tmux
`Discover` = `ScanPTYSessions` (records get the mutagen overlay that tmux records got in `session_discoverer_batch.go:140-163`: LocalPath, MutagenSyncID, Syncing, path pairs) + orphan worktrees + orphan syncs (matched against PTY path pairs) + `enrichHookReports`. Fix: `scanPTYSessionsCmd` (`internal/usecase/session_terminal.go:676-677`) prints an empty list when serve is down, which hides every live session on that host. It must print `AIMAN_SERVE_DOWN`; `ScanPTYSessions` returns `ErrServeDown`; a missing binary still means an empty list. Serve's own `liveSessions` uses `s.pty.List()` in-process.

### Restart and agent switch
The PTY path exists (`restartSession`, `dashboard.go:7655`, branch `7843-7870`: `RecreatePTYSession` + `DeliverInitialPromptPTY`). Delete the tmux env strings and respawn block (`dashboard.go:7784-7827`, `7871-7914`). Move the terminal step into a testable `restartTerminal(...)` in `internal/ui/restart_terminal.go`. `CaptureSessionHandoffBestEffort` uses only the PTY summary capture.

### Removed config and CLI
- `remotes[].session_backend`: ignored with a warning via a shadow YAML decode into `cfg.Warnings` (printed by `cmd/aiman/main.go`, toasted once in the TUI). Never an error.
- `aiman session create --backend`, the `session.create` `backend` param and parent inheritance: ignored/removed.
- Wizard `b` toggle and summary `Backend:` line: removed.
- mosh: `ensureMosh`, `interactiveAttach`, `moshClient`, mosh-only parts of `cmd/aiman/mosh_install.go`: removed (check callers of shared helpers).

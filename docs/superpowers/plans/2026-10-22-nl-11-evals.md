# W10 Harness Evals and Session Ledger Implementation Plan

**Spec:** `docs/superpowers/specs/2026-10-22-aiman-next-level-design.md`. This
plan adds the one harness primitive the Next Level design does not cover: an
evaluation interface. Research input:
`docs/superpowers/research/2026-10-26-harness-research.md` §Thesis, §What the
research adds, and the course's ADR-0017/0022.

## Why this is one plan and not five

The ledger, the fake agent, the scenarios, the metrics and the nightly track are
one capability: "prove a harness change did not break behaviour". Splitting them
would leave each half unusable. The plan is deliberately dependency-light: tasks
1–5 need only nl-1, nl-2 and nl-3a, so the suite can start before nl-5–nl-10
land and protect them as they ship.

## Global Constraints

- Go 1.26; Bubble Tea v2, Bubbles v2, Lip Gloss v2 only.
- `make ci` stays green before every commit. `TestOllamaIntelligenceSummariseSession`
  is a known failure.
- `evals/` is a top-level package inside the module (it may import `internal/`
  because it is under the module root). It must not be imported by any product
  package.
- The fake-agent track is free, deterministic and offline. It must not need a
  remote, a model key, Docker, a network call, or `~/.aiman` outside a temp dir.
- The real-agent track is opt-in (`AIMAN_EVAL_REAL=1`), cost-capped, and never
  runs in `make ci`.
- Deterministic metrics first. A judge is optional and only for report quality;
  a capped run is never judged (the course's task-168 bug).
- `session_events` is appended only by `aiman serve`; other processes read it
  through the socket. No new database. No event bus.
- `evals/` never writes to the product's real `~/.aiman`; the driver sets a
  temp dir and a temp socket.
- Tests that need key events use `pressKey`/`pressRune` (`internal/ui/keystrokes_test.go`).

## Shared state

| Plan | SQLite (serve DB) | Files |
|---|---|---|
| nl-11 | `session_events(session_id, seq, at, actor, kind, payload, hash)` + `session_events_at` index | `evals/testdata/` fixtures; temp dirs only |

`session_events` is an append-only table. `seq` is allocated per session under
the existing per-session mutex; `(session_id, seq)` is the primary key. There is
no migration numbering; use `CREATE TABLE IF NOT EXISTS`.

verification state. Tasks 6–7 run after nl-7 and nl-4 T8/T12 (the usage and
verify cases need `usage.get` and `Review.Passed()`). Task 8 last. This plan is
inserted after nl-4 in the roadmap, with a second slice after nl-7.

```go
type EventKind string
const (
    EventSessionCreated EventKind = "session.created"
    EventPromptQueued   EventKind = "prompt.queued"
    EventPromptSubmitted EventKind = "prompt.submitted"
    EventHookReported   EventKind = "hook.reported"
    EventTodoChanged    EventKind = "todo.changed"
    EventSteerQueued    EventKind = "steer.queued"
    EventSteerDelivered EventKind = "steer.delivered"
    EventHandoverWritten EventKind = "handover.written"
    EventVerifyRecorded EventKind = "verify.recorded"
    EventUsageBudget    EventKind = "usage.budget"
    EventSessionEnded   EventKind = "session.ended"
)
type EventActor string // user | agent | aiman | verifier | system
type SessionEvent struct {
    SessionID string
    Seq       int64
    At        time.Time
    Actor     EventActor
    Kind      EventKind
    Payload   json.RawMessage
    Hash      string // sha256(payload), lowercase hex
}
func (r *Repository) AppendSessionEvent(ctx context.Context, ev SessionEvent) (int64, error)
func (r *Repository) ListSessionEvents(ctx context.Context, sessionID string, since int64, limit int) ([]SessionEvent, error)
func (s *Server) appendEvent(ctx context.Context, sessionID string, actor EventActor, kind EventKind, payload any)
```
`appendEvent` computes the hash and logs (never fails the caller) on a DB error.

  - `TestAppendSessionEventHashesPayload`: same payload → same hash; changed payload → different hash.
  - `TestListSessionEventsSinceAndLimit`.
  - `TestAppendEventNilRepositoryIsNoop`.
  - `TestHookReportAppendsEvent`: a `session.report_agent` call yields one `hook.reported` row with actor `agent`.
  - `TestTodoMutateAppendsEvent`, `TestSteerQueuedAndDeliveredAppendEvents`, `TestHandoverWriteAppendsEvent`.
- [ ] **Step 2: Run** `go test ./internal/infra/sqlite/ ./internal/server/ -run 'SessionEvent|AppendEvent|AppendsEvent'` → FAIL.
- [ ] **Step 3: Implement.** Allocate `seq` with `SELECT COALESCE(MAX(seq),0)+1` inside a transaction under `s.sessMu[sessionID]`. Append from the handlers named in the File Structure. Do not duplicate an event when a handler retries; the caller's operation is the idempotency boundary. The ledger is not a hash chain; the per-row hash is for dedupe and audit, not tamper-proofing.

    Passed  bool

    Score(Result) MetricResult
}

    Name  string
    Setup func(*Harness) error

### Task 4: Lifecycle cases

**Files:**
- Create: `evals/harness/cases_lifecycle.go`
- Test: `evals/harness/cases_lifecycle_test.go`

**Cases (each is a `Case` with deterministic assertions):**
1. `create-ticket` — `session.register` + `session.created` event; `.aiman_task.md` exists when the fake creator writes it; no todo list yet.
2. `prompt-once` — idle hook, `steer.send` free text → exactly one `tmux send-keys`, one `steer.delivered`, no duplicate on a second tick.
3. `steer-held-dialog` — `waiting_input` dialog → no send; then `idle` → one send.
4. `steer-held-working` — `working` → no send; `idle` → one send.
5. `todo-mirror` — agent snapshot changes status only; user text and author survive; a dropped agent item is struck, not deleted.
6. `todo-user-edit-steers` — user add/complete → `todo.changed` + one steer note; an agent-authored change → no note.
7. `handover-restart` — `handover.write reason=restart` → file has Goal/Constraints/Progress/Next Steps/Evidence/Verification; context note exists; `handover.point` queues one note.
8. `handover-precompact` — `PreCompact` report → file written and a compaction-specific pointer queued.
9. `restart-preserves-worktree` — restart path issues no `git worktree remove` / `rm -rf` for the worktree.
10. `terminate-keeps-pane` — terminate leaves the pane snapshot and the session row until archive/forget.
11. `child-spawn` — `session.create --for` links the parent todo with `child:<id>`; child's `ParentID`/group are correct; a Ref-only change does not steer.
12. `event-sequence` — every case's events have contiguous `seq` per session and a stable hash.

- [ ] **Step 2: Run** `go test ./evals/... -run 'Case'` → FAIL.

## Spec deviations

1. **A top-level `evals/` package, not `internal/eval`.** It is course-style
   harness material, not product code; keeping it out of `internal/` makes the
   boundary obvious even though Go permits the import.
2. **The ledger is a table, not an event-sourcing rewrite.** The Next Level
   program already has a hub for live events; this is the durable history the
   hub lacks. `session_events` is append-only and never read on the hot path.
3. **The driver uses `Backend: "tmux"` and a fake remote.** `server.New` takes a
   concrete `*ptyruntime.Manager`, and a fake PTY would test the fake. The
   steering path through `tmux send-keys` is the behaviour under test; the PTY
   layer keeps its own tests.
4. **No LLM judge in the deterministic track.** Report quality is checked by
   keyword/evidence presence, not a model. A judge would add a key, a cost and a
   calibration problem before the deterministic metrics exist.
5. **No new TUI key.** `aiman session log/replay` are CLI; the eval suite is a
   `make` target. The noise budget is unchanged.
6. **The real-agent track is not in CI.** It needs a key, a remote and money.
   The fake-agent track is the CI gate.

## Open questions

1. Should `session_events` be pruned? Proposed: keep 30 days or 100k rows per
   host, whichever is larger; pruning is a later task, not this plan.
2. Should the eval cases assert on the TUI, or only the socket/state? Proposed:
   socket/state first; the PTY conformance harness (README phase 2) owns the TUI.
3. Should `verify.recorded` include the full evidence or only a hash + summary?
   Proposed: summary + hash in the ledger, full evidence in the review JSON.
